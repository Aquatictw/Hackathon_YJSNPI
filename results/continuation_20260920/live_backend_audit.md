## Historical finding — P2: valid source yield disappears before Analysis (source fixed; public repair verified)

- **Cause:** [monitor.py:359](../../grp6_app/monitor.py#L359) emits `run_summary` with `completed_devices`, `good_devices` and `yield_fraction`. [host_relay.py:106](../../deploy/host_relay.py#L106) retains those fields. The generic branch at [exporter-wire.ts:106](../../frontend/lib/rtdi/exporter-wire.ts#L106) omits them from the normalized event. [run-analysis.ts:31](../../frontend/lib/rtdi/run-analysis.ts#L31) reads only normalized `yield`, causing [run-analysis.tsx:92](../../frontend/components/run-analysis.tsx#L92) to show yield unavailable.
- **Reproduction:** pass the existing production evidence through the real relay mapper, POST handler, SQLite-backed repository and snapshot parser in an isolated in-memory database. All 20 supplied summaries disappear from normalized yield records; the final supplied summary is `completed_devices=80`, `good_devices=74`, `yield_fraction=0.925`. Snapshot yield-record count is zero. Predictions and anomaly evidence remain intact. This blocks displaying available measured yield, not HTTPS delivery.
- **Recommended fix:** add a validated `run_summary` normalization branch mapping the supplied `yield_fraction` to `yield` and preserving `completed_devices` with original event/scope/time. Do not derive yield from alerts. Cover this relay-shaped input through snapshot/Analysis in a regression test. Already-ingested summaries need an explicit projection backfill: same-batch retries return early ([repository.ts:92](../../frontend/lib/rtdi/repository.ts#L92)), and identical source events in new batches are skipped ([repository.ts:123](../../frontend/lib/rtdi/repository.ts#L123)); changing normalization alone will not repair stored rows. Preserve original IDs/raw payloads.
